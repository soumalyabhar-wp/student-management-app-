📚 Array vs ArrayList — Comparison

Feature Array ArrayList
SizeFixed at creationDynamic, grows as needed
Type SafetyNo generics supportSupports generics (<Student>)
PerformanceSlightly faster for indexed accessNegligible overhead
MemoryLess overheadSlightly more overhead
Built-in MethodsNone (manual code needed)add(), remove(), get(), contains()…
FlexibilityLow — fixed size, manual resizingHigh — auto-resize, easy CRUD
DeletionManual shifting requiredAutomatic via remove()
SortingManual implementationCollections.sort() integration
Use CaseFixed-size, primitive dataDynamic collections, objects

✅ Why ArrayList Was Chosen For This Project

🔄 Dynamic Sizing

Number of students is unknown at compile time. ArrayList grows and shrinks automatically.

⚡ Built-in Methods

add(), remove(), get(), indexOf() — no manual coding for basic operations.

🗑️ Easy Deletion

Removing a student from an array requires manual shifting. ArrayList handles it automatically.

🔗 Collections Framework

Seamless integration with Collections.sort(), Comparator, and other utility classes.

🛡️ Type Safety

Generics (ArrayList<Student>) ensure compile-time type checking — fewer bugs.

📈 Scalability

System scales effortlessly from 5 students to 5,000 without code changes.

🗂️ Data Structures Used in This Project

  • ArrayList<Student>Primary student record storage
  • HashMap<Integer, Student>O(1) student ID lookup
  • HashMap<String, Double>Subject → Marks mapping per student
  • LinkedList<AttendanceRecord>Chronological attendance log per student
